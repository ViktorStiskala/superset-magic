# Coding standards

The rules code in this repository follows: defect classes an author must avoid while writing and a reviewer can see in a diff.

Two subtree files add the rules for their subtrees: [crates/ss-magic-plugin/CODING_STANDARDS.md](./crates/ss-magic-plugin/CODING_STANDARDS.md) for the plugin crate and the packaged `plugin/` tree, and [crates/ss-magic/src/orca/CODING_STANDARDS.md](./crates/ss-magic/src/orca/CODING_STANDARDS.md) for the Orca files.

What a check already enforces is not restated here: `python3 scripts/build-plugin-zip.py --check` and `--check-bump`, the `cargo tree -i` absence proof, `dist generate --check`, the release-tag shape step, CI's document greps, and the tests that pin invariants.

## Secret safety and sync

The sync engine is the one path that writes untracked (secret) files into the shared main checkout, and `pack` archives the configured files, so both are secret-leak surfaces. The first two rules are load-bearing: breaking either is a secret leak, not a cosmetic bug.

- **Determine "is this a secret?" positively, and fail closed.** A gate deciding whether a path is a secret, tracked, ignored or otherwise safe asks the question whose UNKNOWN answer is the refusing one. Untracked-ness is `!tracked.contains(rel)` over a positively enumerated tracked set (`git ls-files --cached`), never membership in an untracked set: a non-UTF-8, NFD-vs-NFC or otherwise unenumerable name then misses the lookup and lands on the secret side instead of the permissive one. A probe that fails, times out or cannot be asked answers "no" to every permissive question. See [docs/solutions/logic-errors/secret-gate-positive-tracked-determination-fail-closed.md](./docs/solutions/logic-errors/secret-gate-positive-tracked-determination-fail-closed.md).
- **Enforce a secret-excluding path filter at the point of final enumeration, not on an upstream list.** The excluded trees (core's `sync::EXCLUDED_TREES`: `.superset/backups`, `.superset/.magic`, `.scratchpad`, `.git`) are filtered in every step that re-reads the live filesystem after the match set is decided – archive building, recursive directory copies, source walks, reverse sync's candidate computation. Filtering the flat match list alone is not enough: a directory match that is an ANCESTOR of an excluded tree (a bare `.superset`, a broad `**`) re-admits the whole subtree through the walk, and one such match can sit above several excluded trees at once. Matching is by whole path component, never a string prefix or a bare name, and `.superset` itself is never excluded (that would drop the contract files out of sync and pack). A comment asserting "X is never included" is a defect unless the guard sits in the walk, and the test exercises the ancestor-directory match, not only the leaf. See [docs/solutions/logic-errors/pack-backups-exclusion-must-guard-the-directory-walk.md](./docs/solutions/logic-errors/pack-backups-exclusion-must-guard-the-directory-walk.md).
- **Make secret bytes ignored in the destination before they land, and verify it strictly.** A write that puts an untracked source into the shared main checkout first ensures the path is gitignored there, then re-verifies with git and aborts with nothing written if it is still not ignored. The re-verification runs in release builds – never behind a `debug_assert!`. A tracked, already-committed source never gains a `.gitignore` rule. `--no-backup` skips only the backup copy, never this gate or the concurrent-edit guard.
- **Copy an ignore rule only at the scope it was written for.** A covering rule found by `git check-ignore -v` means something only relative to the `.gitignore` it came from. Before copying it into another root, verify it covers the path there; otherwise write an anchored literal. A nested `*` re-anchored at a broader root ignores far more than the one path.
- **Never follow a symlink into an archive.** Classify each match with `symlink_metadata` (no-follow): `Path::is_dir()` and `is_file()` follow links, so a top-level `is_file()` guard is no substitute, and a matched link to a directory would walk the target tree outside the repository. Archive builders set `tar::Builder::follow_symlinks(false)`, because the default embeds the target's bytes – a link to `~/.aws/credentials` puts that file in the archive. A link is stored as a link. See [docs/solutions/tooling-decisions/rust-tar-bzip2-archive-crate-gotchas.md](./docs/solutions/tooling-decisions/rust-tar-bzip2-archive-crate-gotchas.md).
- **Never replace good output with empty output.** When nothing was actually added (every match vanished or was a special file), the staged archive is discarded and an existing one is left untouched. Pack never archives its own output (any root-level `ss-magic-*.tar.bz2`) or a match that resolves to the repository root.
- **Guard every destructive write against changes made since the review.** An overwrite or delete first takes a timestamped backup of the losing bytes under the gitignored backups tree of the root being overwritten, and re-checks each side – the source included – against a baseline captured when the user SAW the state, not one taken next to the write (two adjacent snapshots can never differ, so such a guard never fires). The change signal is length plus mtime, or a content hash when the filesystem reports no mtime; a bare length never passes as unchanged. A side the review classified as absent is pinned absent, so a file that appears there during the review is skipped, not clobbered. A stat error other than "not found" counts as changed. See [docs/solutions/logic-errors/toctou-guard-review-time-baseline.md](./docs/solutions/logic-errors/toctou-guard-review-time-baseline.md).
- **One bad file never aborts the batch.** A read, stat or hash failure on one candidate degrades that file – to "skipped" or to an explicit unreadable state that names the failing side – and never propagates out of a classification, baseline-capture, load or apply loop. The degraded path fails closed (it skips, never overwrites what it could not read), never substitutes empty content for an unreadable side, and still shows in the summary and the exit status. A direction gate checks WHICH side failed: a readable main copy can still be pulled over an unreadable worktree copy. A walk over a live directory tolerates an entry that vanished between listing and stat.
- **Order side effects after the checks that can abort them.** Read the source before mutating the destination, so a failed read leaves no stray `.gitignore` rule behind. The ignore rule lands before the secret bytes do. A merge, which writes both sides, runs the ignore gate, then writes main, then the worktree, so a failure before main's write leaves both sides untouched instead of split. A two-sided delete removes main's copy before the worktree's, so a failure leaves the worktree copy – and the next run's candidate – intact.
- **A rewrite of a configuration file preserves everything it does not own.** Writers load, modify and write the whole typed config, whose flattened `extras` map carries keys a newer build or a hand edit added. `config.json`'s `teardown` and `run` survive a `setup` rewrite; the person's own `setup` commands keep their place, a retired reference is replaced in place, and no second entry is added that runs the sync again. User-typed patterns survive a re-run. An optional list keeps its two empty states apart – absent ("never chosen") versus `[]` ("chose none") – and a per-machine overlay never reaches a committed output.
- **There is one glob and exclude engine.** Expansion goes through core's `sync/apply.rs` (`run`, `run_filtered`, `match_paths`) and syntax through `pattern::check_syntax`. Absolute patterns and any `..` segment are rejected; `DEFAULT_EXCLUDES` names drop a match at any depth; `globset`'s `*` crosses path separators, unlike a shell glob. A `PathFilter` is applied at every enumeration point (each match and inside the recursive directory copy), like the excluded trees.
- **A retention sweep knows every layout the tool ever wrote.** Deletion is allow-listed by the exact name shapes the tool wrote, current and legacy, and never touches a foreign entry. The batch the current run wrote is protected by name, because a backward clock jump can make it sort as "older" than the keep set. Pruning is best-effort: a failure warns and never fails the operation. A retention test seeds every historical layout. See [docs/solutions/logic-errors/retention-must-know-every-layout-ever-written.md](./docs/solutions/logic-errors/retention-must-know-every-layout-ever-written.md).
- **Splicing independently sourced text treats a missing trailing newline as its own case.** When region A does not end with a line terminator, concatenating region B fuses two lines. Tests include a fixture whose first side lacks a final newline. See [docs/solutions/logic-errors/merge-assembly-line-fusion-missing-separator.md](./docs/solutions/logic-errors/merge-assembly-line-fusion-missing-separator.md).
- **Diff and merge from normalized text; copy raw bytes.** Diff and merge inputs are EOL-normalized so hunks reflect content only, and a pair equal after normalization is shown as "line endings only", not hidden. Push and pull copy the raw on-disk bytes, and byte classification stays byte-exact.
- **Engines emit events; the rendering layer does the printing.** The apply and pack engines report through a caller-supplied event closure and never print. The clipboard copy and the extraction hint hang off the rendering layer, so tests that drive the engine never touch the developer's clipboard.
- **Generated files come from their one source.** The `.superset/magic.sh` body is the embedded `assets/magic.sh` and nothing else; the legacy `setup_config.json` is read for migration and never written.

## Git plumbing

- **Parse-sensitive git output must not go through a trimming convenience wrapper.** Core's `git()` and `git_optional()` trim the whole output, which is right for one value and destructive for a fixed-column format: `git status --porcelain`'s first column is a literal space for a worktree-only modification, so trimming shifts every field of the first line. Porcelain, `check-ignore -v`, NUL-separated and column-indexed output goes through `git_raw` and is split per line without a per-line trim. See [docs/solutions/logic-errors/trimming-wrapper-corrupts-porcelain-status.md](./docs/solutions/logic-errors/trimming-wrapper-corrupts-porcelain-status.md).
- **Every git and gh command lives in core's `git/mod.rs`.** Other modules call its functions and never spawn `git` or `gh` themselves. Inside it, git commands go through `git_raw` (stderr surfaced verbatim) or its thin `git` / `git_optional` wrappers; only `gh` and a git call `git_raw` cannot serve (feeding stdin, as `ignored_untracked` does, since `git_raw` nulls it, or reading only an exit status) build their own `Command` there. No git-binding crate (`git2`, `gix`) is added.
- **The filesystem-only root discovery answers two questions, or declines.** Core's `git/discover.rs` reduces exactly `rev-parse --show-toplevel` and `--git-common-dir` to a filesystem walk, and only the plugin crate calls it; CLI commands keep the subprocess probes. It never reads refs, the index, or more of the config than the repository-format check, and never writes. A fast answer is byte-equal to git's or there is none: widening the decline set is always safe, while turning a decline into an answer, or changing an answer, needs a real-git scenario in the equivalence matrix.
- **A bulk ignore probe reports only what git positively said.** `git check-ignore` consults the index, so it never reports a tracked path; adding `--no-index` would. Git reads each candidate as a pathspec, so the probe itself drops a candidate that is empty or starts with `:` (`:(top)a.env` would be answered as `a.env`; `:!x` aborts the batch), and callers drop one inside a submodule or beneath a symlinked directory, which also aborts the batch. The candidate list is written from a helper thread while stdout drains, so a list larger than a pipe buffer cannot deadlock. A git failure means "nothing is ignored".

## Filesystem writes

- **Replace a file by staging and renaming, with an exclusive staging file.** A tracked or shared file is never written with a truncating `fs::write`: the new content goes to a sibling in the same directory and is renamed over the target, so a write that dies half-way leaves the previous file, not a prefix. The staging file is created with `create_new` (`O_EXCL`); an existing entry at the staging name is unlinked (the link, never its target) and recreated, because a plain write would follow a symlink planted there. An archive is persisted only after every stream layer is finalized. The `.superset/` tree is staged whole and copied into place only after the finishing prompt.
- Which writer follows a link at the target name, and which refuses a target resolving outside the repository, is decided per writer: see [crates/ss-magic-plugin/CODING_STANDARDS.md](./crates/ss-magic-plugin/CODING_STANDARDS.md) for the `magic.json` writers and [crates/ss-magic/src/orca/CODING_STANDARDS.md](./crates/ss-magic/src/orca/CODING_STANDARDS.md) for the explicit and the automatic Orca writes.

## Failure reporting

- **The exit status reflects what happened.** A batch exits non-zero iff a file failed. A command that refuses to run non-interactively (the Sync cockpit without a TTY exits 2) never exits 0. A best-effort step – pruning, an automatic refresh – warns and never changes the exit status. "Could not check" is never reported as "already up to date": a failed release resolution is `Unavailable`, distinct from `AlreadyLatest`.
- **Summaries count only what was done.** A directory match whose every file was filtered is not reported as copied; a path deliberately left alone is tallied apart and never turns a summary into a warning; a run that archived nothing does not print "Packed 0 files". A count names unique file paths, not raw entries.
- **A prompt describes exactly the action that runs.** The confirm lists every overwrite and delete, naming the exact sides a delete removes, and the badge and the confirm derive those sides from one function. A message states the outcome for every side the operation could touch: a cancel in a two-way flow says "worktree and main untouched", not "main untouched".
- **Malformed configuration is a hard error naming the path.** Wherever the overlaid config decides what is copied or archived, a parse error stops the command with a non-zero exit, never a silent fallback to empty. The one exception – init, edit config and migrate planning Orca's file list – prints a warning to stderr and carries on, because leaving those patterns out is safe (forward sync still copies them).

## TUI

- **Construct the terminal-restore guard right after the first fallible setup step.** The panic hook is installed before raw mode is enabled and the `Drop` guard is constructed immediately after `enable_raw_mode()`, before the alternate screen is entered, so a panic or an early `?` can never strand the terminal in raw mode. See [docs/solutions/design-patterns/ratatui-terminal-restore-guard-ordering.md](./docs/solutions/design-patterns/ratatui-terminal-restore-guard-ordering.md).
- **Never clip content silently.** Popups are sized to their content, not to a percentage of the frame, and a list that cannot fit ends in an explicit truncation marker while the prompt stays visible. Long diff lines scroll horizontally under FIXED line-number gutters, the pane title says when lines continue, and the offset resets per file. Long paths wrap instead of being cut. A notice that must stay visible sits in a fixed header row, not the scrolled body. When popup content grows, a render test at 80x24 asserts its LAST line is on screen – asserting the first line only proves the popup opened. See [docs/solutions/design-patterns/ratatui-popup-content-sizing.md](./docs/solutions/design-patterns/ratatui-popup-content-sizing.md).
- **Nothing is pre-selected, and every key is an explicit action.** Every file starts undecided in either direction; applying needs the one batched confirm, keyed Enter = apply / Esc = back, with no default-No idle path. Cancellation (Esc, Ctrl-C) is inert and leaves both trees untouched. An interactive surface refuses to launch without a TTY and writes nothing. A key that does not apply to a file (merge on a binary or one-sided file) is a no-op with a notice.
- **The split and unified diff colors stay mirrored.** Main is the base and local the working copy in both views: local text green, main text red. Recoloring one view without the other is a defect.
- **A picker whose rows carry actions is a `Select` loop.** `inquire::MultiSelect` commits the whole selection on Enter, so an action row ("Add new pattern…", "Done") placed in it never fires; state lives outside inquire and each row is an action. See [docs/solutions/design-patterns/inquire-action-loop-2026-05-26.md](./docs/solutions/design-patterns/inquire-action-loop-2026-05-26.md).
- **Keep pure logic out of the interactive layer.** Glob expansion, config merging and path resolution live in testable modules, not in `tui/menu.rs`, `tui/ui.rs` or `main.rs`, and no `inquire` call enters a pure module.
- **Color goes through core's `style.rs` only.** It respects the one `NO_COLOR` / supports-color decision; no raw ANSI escapes elsewhere.

## Tests

- **A test whose subject is the process environment runs its assertion in a child process.** `PATH`, a `GIT_*` variable or the working directory are set only in a child spawned through `testutil::run_ignored_test_in_child` (or its `_from` variant), never with `set_var` / `set_current_dir`: the suite is multithreaded, and every `git` another thread spawns inherits the value, whatever lock guards the setter. A per-file `ENV_LOCK` around `set_var` is acceptable only for a variable no concurrent test's child reads (`HOME` in the checklist-deny tests, the update loop-guard variables). Code that reads environment variables a launching terminal may carry (the Orca variables) takes an injected lookup, so a suite started from such a terminal behaves the same.
- **No test depends on the real date or the crate version.** A fixture timestamp never reaches code that reads the real clock – pass the clock in. "The running version" is `env!("CARGO_PKG_VERSION")`, never a literal, and a "newer release" fixture sits far ahead of any plausible bump. A test coupled to either goes red on a merge that touched nothing near it. See [docs/solutions/logic-errors/cargo-dist-plan-job-failure-publishes-empty-release.md](./docs/solutions/logic-errors/cargo-dist-plan-job-failure-publishes-empty-release.md).
- **Fixture repositories are deterministic and isolated.** Every fixture repo sets `gc.auto = 0` (a commit can spawn `gc --auto`, which deletes entries under `.git` mid-walk) and a repo-local `core.excludesFile = /dev/null`, so a developer's global ignore file reaches neither the helper's git nor the production code's own shell-outs. Use the shared `testutil` helpers that already do both.
- **Test the shape the bug lives in.** A secret probe's test gitignores the secret and asserts that precondition, so it cannot pass vacuously on the non-ignored shape. A line-oriented parser gets a single-line fixture (a first-line-only defect hides behind multi-line input), and porcelain covers the worktree-only ` M` case. See [docs/solutions/logic-errors/reverse-sync-untracked-probe-excludes-gitignored-secrets.md](./docs/solutions/logic-errors/reverse-sync-untracked-probe-excludes-gitignored-secrets.md).
- **New behavior in a pure module comes with tests.** Cover the happy path and the edge cases (empty input, hard-fail paths, exclusions). A bug fix's regression test is the one [REVIEW.md](./REVIEW.md) asks for: revert the guard and confirm the test goes red.
- **Tests live in a sibling file.** Each module declares `#[cfg(test)] mod tests;` with the body in `<module>/tests.rs`, never an inline `mod tests { … }`. Core's `testutil` feature is enabled from a binary's `[dev-dependencies]` only, never from `[dependencies]`, which would compile test helpers into a release binary.

## Release, CI and dependencies

- **Bump the CLI version on any change to CLI behavior.** A fix, a new or changed command or flag, or different output bumps `crates/ss-magic/Cargo.toml` and its `Cargo.lock` entry (matched on the `name = "ss-magic"` line and regenerated by `cargo build`, never a blind replace); the installed binary self-updates keyed on that version, so a stale one means users never receive the change. Bug fixes bump patch, user-visible behavior minor. Bumps follow the release line, never the repository; the plugin line's bump and the two lines' distinctness are checked.
- **A publish gate is checked by the job that publishes.** cargo-dist's `host` job publishes when each build succeeded OR WAS SKIPPED, so a gate upstream of the builds that `host` does not check can fail, skip every build and still publish a release with no assets – and an immutable release with a protected tag burns that version for good. The test gate is a `local-artifacts-jobs` entry, never `plan-jobs`; the generated `release.yml` is regenerated, never hand-edited (both checked). Push a release tag only after CI on `main` is green for that exact commit. See [docs/solutions/logic-errors/cargo-dist-plan-job-failure-publishes-empty-release.md](./docs/solutions/logic-errors/cargo-dist-plan-job-failure-publishes-empty-release.md).
- **A job that gates a release has a timeout.** Without `timeout-minutes`, a wedged test run stalls PRs and tag-triggered releases for GitHub's 360-minute default.
- **The plugin zip's extra artifact stays on the plugin crate, with `working-dir = "../.."`.** At workspace level it would attach to every release, the CLI's included. A package-level build command resolves against the crate root, so without `working-dir` it fails in `build-global-artifacts`, after the tag is pushed and invisibly to `dist plan`; verify a change with `dist build --artifacts=global`.
- **Attestation stays in the build-local phase.** `github-attestations` signs same-job build output before it transits Actions storage; a host- or announce-phase attest signs a merge directory any job in the run can inject into, so moving the phase is a security decision, not a routine change.
- **The self-updater installs only a pinned tag of its own release line.** The release check filters tags with an anchored, exact match (the line's prefix plus three ASCII-digit components, nothing after), drops drafts and prereleases and takes the GREATEST triple, never the first entry or `releases/latest` – one repository hosts both lines, and an unanchored `v` match would read a plugin release as a CLI one. Every apply entry point takes a mandatory tag (signatures pinned by a compile-time test). The check uses a short timeout and falls through silently on any failure; the next cache record has one derivation; the re-exec loop guard keeps a re-executed child out of the update gate, and a new command is added to the gate's inclusion list deliberately.
- **Dependencies stay as chosen.** No `clap` (both argument parsers are hand-rolled); no hashing crate (core's `hashing.rs` holds FNV-1a and a SHA-256 pinned by test vectors); `bzip2` on its default pure-Rust backend with no feature flag, so no C toolchain is needed; `[profile.release]`'s `opt-level = "z"` is a measured workspace-wide decision with no per-crate override. Which crates the plugin and core may not link is checked.

## Shell scripts

- **Write for bash 3.2.** macOS ships it: no associative arrays, no `mapfile`, no `${var^^}`, and no `case` arm inside `$( … )`, which does not parse there. CI runs the shell suites under `/bin/bash` 3.2 on macOS, which proves only the lines they exercise.
- **A `read` loop handles an unterminated last line.** Write `while IFS= read -r line || [ -n "$line" ]`; without it the last record is dropped, and in a newest-last list that is the one the script exists to find.
- **Sort numerically on whole fields.** Split on the separator and key each field (`sort -t . -k 1,1n -k 2,2n -k 3,3n`); a mid-field key such as `-k 1.2,1n` is not numeric on BSD sort, and a lexical sort puts `v0.11.10` before `v0.11.3`.
- **Shell suites share one assertion harness.** Counters and `assert_*` helpers live in `scripts/lib/test-harness.sh`, sourced by every suite, so the suites cannot drift apart.

## Maintaining this file

- A rule enters only with evidence – a review finding the author fixed, a fix commit, a cleanup that removed the defect across the codebase, or a `docs/solutions/` record – and only when no check covers it. A rule already stated in a contributor-instructions file or in [.cursor/BUGBOT.md](./.cursor/BUGBOT.md) belongs too. A check that enforces a rule earns at most a one-line mention.
- State each rule as a condition, in a few sentences that stay true without volatile numbers or symbols, and link the `docs/solutions/` record that owns its detail.
- Group rules by area. Rules for the plugin crate and the `plugin/` tree belong in [crates/ss-magic-plugin/CODING_STANDARDS.md](./crates/ss-magic-plugin/CODING_STANDARDS.md), Orca rules in [crates/ss-magic/src/orca/CODING_STANDARDS.md](./crates/ss-magic/src/orca/CODING_STANDARDS.md).
- Update the file in the same change that establishes or retires a rule.
- `.cursor/BUGBOT.md` is self-contained and cannot link here: restate the changed rule there in the same change.
